## New post

**Nº 127 - "How to catch Shopify orders where half the order never ships"**
`how-to-catch-shopify-orders-where-half-the-order-never-ships.html` - Priya Singh - 2026-10-14 - 2,367 words - 8 min

Pain point: part of an order ships, the rest never does, and the leftover is invisible rather than
merely forgotten. Shopify marks the order Partially fulfilled and then stops: no owner, no clock,
no aging, and crucially no report, because report filters work at the order level rather than the
line item level. The bigger the order, the better hidden the remainder.

Facts used, all checked live this run:
- Help Center, order status: "When you fulfill part of the items in an order" is the whole
  definition of Partially fulfilled. Also documented there: On hold (checkout upsell offers set a
  temporary hold; releasing returns items to Unfulfilled), Scheduled (prepaid subscription orders),
  In progress (set manually, e.g. while picking), and Fulfillment not required, which the
  Unfulfilled view excludes. The page names no report or alert for orders that stay partially
  fulfilled.
- Admin GraphQL, OrderDisplayFulfillmentStatus: eleven values. PARTIALLY_FULFILLED is "Some of the
  items in the order have been fulfilled". IN_PROGRESS is "a request for fulfillment sent to the
  fulfillment service". ON_HOLD, SCHEDULED and REQUEST_DECLINED round out the set of statuses that
  mean work is outstanding while reading like a conclusion.
- Admin GraphQL, FulfillmentOrder: "either an item or a group of items in an Order that are
  expected to be fulfilled from the same location", created automatically by Shopify, not creatable
  by hand, and more than one can exist per order at a given location. Also: "Multiple fulfillments
  can exist for a single order when items either ship separately or from different locations."
- Shopify Community, 7 Aug 2026 (ChipWiley): "When filtering reports by fulfillment status, the
  filter operates at the order level, not the line item level." Order #2312, 25 items, 24 fulfilled,
  1 unfulfilled, absent from the unfulfilled items report. Mentions the support chatbot's feedback
  link returning a 404. No staff reply, unresolved. This is the spine of the post.
- Shopify Community, 20 May 2026 (Breno_Freitas): "Currently, the ShopifyQL `FROM sales` dataset
  does not expose a `line_item_fulfillment_status` field for filtering." Reply (lumine) does not
  expect ShopifyQL to add it soon and points to the GraphQL `fulfillmentOrders` query instead. No
  staff reply.
- Shopify Community, 15 May 2024 (wiredigital): wanted to isolate orders where one specific item was
  the unfulfilled line. Answer was a Flow with a for-each loop, plus the note that Flow has no
  action that marks an order itself as fulfilled, only fulfillment orders. A second merchant
  (Priyanka_1, 8 Aug 2024) asked whether it ever worked. No answer.
- Shopify Community, 18 Jul 2024 (F3arl3ss): "struggling to keep up with demand and often partially
  fulfils orders", asking for "a way to tweak the email templates to show the line items that are
  unfulfilled". One reply suggests testing `fulfillment.fulfillment_line_items`, documented as "A
  list of fulfillment line items to be fulfilled", unconfirmed. Thread open.
- Shopify Community, 2 Oct 2023 (dazzled): two items, one shipped, one cancelled by the vendor;
  asked how to update the order and why the customer was not notified. One merchant reply: refund,
  email the reason, write an SOP. No staff answer.
- Flow trigger "Order fulfilled": the page body says it "starts a workflow when fulfillment of one
  or more line items in a fulfillment order is successful" and warns "it is possible for this
  trigger to start a workflow multiple times for the same order", while the same page's meta
  description says it starts "when all the line items in an order are fulfilled". The docs
  contradict themselves. Behaviour is the body text, so anything hung off Order fulfilled fires on
  half orders.
- Full Flow trigger reference cross-checked. The fulfillment bench is long (fulfillment created,
  fulfillment event created, fulfillment order placed on hold, holds released, merged, split,
  moved, rescheduled, ready to fulfill, line items prepared for pickup or local delivery,
  fulfillment request submitted/accepted/rejected, cancellation request submitted/accepted/rejected,
  and fulfillment service failed to complete fulfillment). None fires on a remainder that is simply
  sitting.
- Flow "Scheduled time" trigger: "limited to run a maximum of one time every 10 minutes", repeat
  intervals in whole days, weeks or months, longest interval one year, needs at least one future
  occurrence, and supplies no event data, so a Get order data step plus a loop is required. That is
  the only native route to an aging sweep.

## Why this topic
High demand, thin supply. Everything written about partial fulfillment on Shopify is a how-to for
*doing* it (stoqapp, banzota, hulkapps, extuitive, integrately all rank). Nobody has written the
detection and follow-through problem: the order-level report filter, the missing ShopifyQL field,
the four statuses that read like conclusions, the customer who is told half the story, and the Flow
trigger that fires on half orders. Complaint threads run 2023 to August 2026 with no staff replies
and no resolutions, which is demand without supply. It is also seasonally timely: six weeks to BFCM,
when split shipments spike.

vendor content), POS and online inventory sync lag (carried forward again, still a decent
