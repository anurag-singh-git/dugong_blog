# QA report, 2026-11-19

Scheduled QA pass over blog.dugong.live, run against the mounted repository
after the day's publishing run had shipped dispatch Nº 144 and after the
SEO/GEO pass had finished. Final state: 111 rendered pages, 82 redirect stubs,
98 dispatches, 110 sitemap URLs, 98 feed items.

A whole-site snapshot was taken before the first write at
`_qa_tmp/run-11-19-qa/site.tar.gz`. All measurement was done on a copy of the
tree in the cloud container, the fixes were written and verified there, and
only then applied to the repository with the same two idempotent scripts, kept
at `_qa_tmp/run-11-19-qa/qa-fix-2026-11-19.py` and
`_qa_tmp/run-11-19-qa/checker-patch-2026-11-19.py`. The two trees were then
compared by digest over all 574 content files and are byte identical
(`_qa_tmp/run-11-19-qa/digests-after.txt`), so every measurement below
describes the repository as it now stands.

Three method notes, all three corrections to what this file has been leaving
behind.

**The tree moved under the pass, and the pass noticed.** The snapshot was
taken at 10:46. At 10:51 and 10:52 the SEO/GEO run wrote to `index.html`,
`shopify-automation-questions.html` and `_tools/seo-check.py`, and it finished
at 11:00. Three of the sixteen files this pass was about to write had changed
underneath it. The fixes were rebased onto a second snapshot taken at 11:55,
re-verified end to end there, and only then applied. **Two scheduled runs
share this repository and neither announces itself**, so the hash check
against the snapshot has to happen immediately before the write and not only
after it. The SEO run's edits, JSON-LD `mainEntityOfPage` fields and md
rendition changes, did not collide with anything here, which is luck rather
than design.

**The pixel channel of the render diff was reporting itself.** A control run
of the pre-fix tree against a byte-identical copy reported 6 differing
page-widths; the identical run again reported 10, on different pages; with a
capture-stability gate added, 45. The same pages compare byte-identical when
captured three times in a short-lived process, and a bounding-box diff under
reproduced conditions finds zero differing pixels. A full-page capture of a
13,000px page in a long-lived process is not reproducible here, and by this
file's own rule a channel that cannot report the same page twice the same way
is reporting the harness. It was removed from the whole-site sweep rather than
kept with the flake written off as noise. What replaced it is stronger: the
geometry channel now records position, size, colour, background, background
image, border colour, style and width, opacity, font size, weight, family,
line height, letter spacing, display, position, white-space, overflow,
text-overflow and visibility for every element on every page. The control run
of that is **0 of 444 page-widths**. Pixels are still compared, on the pages
that actually changed, in a short-lived process where the capture is provably
stable.

**A focus-ring sweep that calls `el.focus()` lies.** Scripted focus does not
reliably match `:focus-visible` in Chromium, and the first sweep reported 60
card links with no focus ring on every page carrying a card grid. Driving real
`Tab` presses instead, every stop on seven sampled page types has a visible
ring. Recording it because the false version is the easy one to write and
would have gone into this report as a finding on 109 pages.

## Fixed

### 1. The homepage announced its nav and its footer as main content

`index.html` wrapped the entire document, ticker, header and footer included,
in `<div class="view home active" id="view-home" role="main">`. The other 110
pages put the landmark on the article and leave the header and footer as
siblings. The consequence on the most-crawled page of the site: `main`
contained the whole page, so the landmark carried no information at all, and a
screen-reader user jumping to main landed on the marquee. axe reported
`landmark-banner-is-top-level` and `landmark-contentinfo-is-top-level`, **the
only two automated accessibility violations anywhere on the site**, and they
had stood since at least 11-18, where this was recorded as standing because it
is DOM surgery and `.view` is load-bearing for the homepage's view switching.

It is DOM surgery, and it is four lines:

- `role="main"` comes off the `.view` wrapper, which keeps its class and its
  id and goes on switching views exactly as before;
- a `<main id="main" role="main">` now opens after `</header>` and closes
  before `<footer class="foot">`, holding the nine content sections and
  nothing else;
- `id="main"` moves off `<section class="hero">` onto that landmark. The two
  start at the same y, so the skip link lands exactly where it did, and it now
  lands on the landmark rather than beside it;
- the six `.view.active.home > .hero > *` entrance rules lose their child
  combinator, because there is one more element between them now. Sampled at
  0, 120, 300, 600 and 1200ms before and after: the `rise` animation runs on
  the same curve with the same staggered delays.

### 2. Seven sections on the homepage had no accessible name

With the wrapper in (1) gone, the homepage's hand-written sections are no
longer inside a landmark by accident, and seven of the nine had nothing to
name them. This is the 11-18 finding exactly, on the one page that pass had to
exempt. Each now names the text already on screen, so the accessible name is
what the reader sees: the hero and the signup block reference their own
headings, the other five reference the `section-eyebrow` that was already
there. `aria-labelledby` rather than `aria-label` for the same reason 11-18
gave, and every reference was checked to resolve before the fix was applied.

`section_name_exempt` in the checker has been emptied with the reason written
in the file, per the instruction that pass left: *if it is ever fixed, drop
this exception and name them.*

After: axe reports 0 violations of any rule on all 111 pages at both widths,
the first time this sweep has come back empty.

### 3. The playbook mock cut text the reader could not get back

`.pb-node-sub` carried `white-space: nowrap` with `overflow: hidden` and
`text-overflow: ellipsis`. Three lines of the DISPATCH OF THE WEEK playbook
mock on the homepage ran past their box:

| line | plain | under the 1.4.12 override |
|---|---|---|
| `type, vendor, weight, tags, title pattern` | 112px cut at 320, 57 at 375, 73 at 1024 | **181px cut at 1280** |
| `unrated countries and locations → #ops` | 91px cut at 320, 36 at 375 | 155px at 1280 |
| `plus every product you create` | 26px cut at 320 | 75px at 1280 |

The second column is the finding. Those lines render in full at 1280 with no
override, and a reader who sets their own letter spacing loses them. Content
lost to the reader's own spacing preference is exactly what WCAG 1.4.12
forbids, and an ellipsis is an affordance only where there is some other way
to read the text. There was none: no title, no expansion, no wider viewport
that helps.

Replaced with `overflow-wrap: break-word` and no truncation. Rendered and
looked at before and after at 390 and 1280. The three lines now wrap onto a
second line on a phone, which is the grammar the mock already uses directly
below them, where the IF/ELSE branch block has wrapped onto two lines since it
was written. At 1280 and 768 nothing moves at all; the element screenshot of
the mock is md5-identical before and after.

The rule lives in 16 pages' stylesheets and the markup in one, so 15 of those
edits change nothing today and close the class, the same reasoning as
`article_title_does_not_wrap` on 11-18.

## The 194 prose hits that are not defects

Recording the raw number because it is the kind that gets copied into a report
as a finding.

- **129 British spellings**, every one of them `cancelled` or `cancelling`.
  The site writes `cancelled` 499 times against 14 of `canceled`, and all 14
  of those are quoting Shopify's own UI strings: the `Canceled` run status in
  Flow, the `Order canceled` trigger name, the *Canceling orders* help page.
  `cancelled` is the house spelling and the 14 are correct as literals. The
  check's pattern list, not the site, was wrong.
- **31 missing spaces after a period**, all dotted API paths:
  `product.metafields.namespace.key`, `destination.location`,
  `Order.transactions`, `theme.liquid`.
- **21 a-before-vowel and 10 an-before-consonant**, all correct by sound:
  *a URL*, *a UPS*, *a USPS*, *a US*, *a UK*, *an SEO*, *an FTP*, *an SOP*,
  *an RTO*, *an RTS*, *an SMS*, *an llms.txt*, and *supplier A and anything
  over a certain weight*.
- **2 doubled words**, both correct English: *what a customer is is not a slot
  to fill*, *double opt-in in particular*.
- **1 loose hyphen**, inside the verbatim title of a community thread.

Zero mojibake, zero raw entities, zero placeholder text, zero unbalanced
brackets or quotes, zero em or en dashes, zero double spaces.

An earlier version of the extractor read a non-block container's own text
nodes separately from its inline children, which turned
`the <strong>$84</strong>, the <strong>goods</strong>` into *the , the*, and
produced 281 phantom punctuation hits and a phantom *the the*. Treating any
element with no block-level child as one text block fixes it, and the phantom
hits went to zero without a single exception being added. **A prose checker
that cannot read a sentence the way it is rendered is checking its own
extractor.**

## Checked and found by design

- `div.ticker` overflows its box on 99 pages at every width. It is the
  `aria-hidden` marquee; the overflow is the effect.
- `div.cta-band-inner` on 35 pages and `div.signup-inner` on 1 overflow by
  exactly their `::before` offsets, 90px and 70px. Both pseudo-elements have
  `content: ""` and paint a decorative glow. No text is involved, which the
  contrast check already handles the same way.
- Every contrast hit below AA, 307 page-widths of them, is the `·` divider
  between byline items at `rgba(15,15,12,.45)`, ratio 3.03. Every one is
  `aria-hidden="true"` and is a visual separator carrying no information,
  which is the decoration exception to 1.4.3. Verified that all such spans
  site-wide carry the attribute: 0 without it.
- `404.html` still carries no `<header>`, `<nav>` or `<footer>`, unlike the
  other 110 pages. It has a main landmark, a focus ring, a reduced-motion
  block and 24px targets, and its two buttons plus ten latest dispatches are a
  better 404 than the site nav would be. Not a finding, but it is the page
  that has needed a hand-written patch on 11-02, 11-04 and 11-18, and it is
  the only page this pass did not touch that is not written by anything.

## Standing, not fixed

**The signup form tells the reader they subscribed when nothing happened.**
Unchanged from 11-18 and now two passes deep. `index.html` still carries

```
onsubmit="event.preventDefault();
          this.querySelector('button').textContent='subscribed ✓';
          this.querySelector('input').value='';"
```

The address is not sent anywhere, not stored and not recoverable: the handler
clears the field and writes a success message, beside fine print reading
"free · unsubscribe anytime · 4,200 readers". This is the most reader-facing
content defect on the site and remains the one thing in this report a pass
should not fix unattended, because all three honest repairs are product
decisions: point the form at a real provider, which needs an account and a
key; replace it with the RSS feed the site already publishes, which is a real
subscription and one link; or keep the field and say plainly that the list is
not open yet. The second needs no infrastructure and is honest today. Flagging
rather than choosing, for the second time.

**No print stylesheet.** Unchanged from 11-17 and 11-18, now three passes
deep. The blocker is unchanged: `.related` is navigation on a dispatch and
content on a topic guide, so one rule cannot serve both without a page-type
hook in the markup, which is a change to all 111 pages.
`_qa_tmp/qa-fix-2026-11-17.py` still holds the block that was tried.

**Two scheduled runs write to this repository and neither knows about the
other.** New here, and it is the method note above promoted to a finding,
