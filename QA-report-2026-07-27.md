### 3. Unescaped `&` in the Google Fonts link, 141 occurrences across 47 files

Every rendered page carried:

```html
<link href="https://fonts.googleapis.com/css2?family=…&family=Inter…&display=swap" …>
```

Three raw ampersands per page. This has been carried as a known open item for several passes on the
grounds that browsers parse it and it is how Google's own snippet ships. Both are true, but it is
still the site's only remaining HTML validity error, `&amp;` is the correct encoding, and browsers
decode `&amp;` back to `&` in attribute values so the request URL is byte-identical. Fixed rather
than carried forward again.

Scoped strictly to `href="https://fonts.googleapis.com/…"`; no other ampersand anywhere on the site
was touched. Post-fix, **bare-ampersand count across all 93 HTML files plus feed.xml, llms.txt and
sitemap.xml is 0.**

### Not changed: URLs

Diffed the full set of `canonical`, `og:url`, JSON-LD `@id` and sitemap `<loc>` values against HEAD.
The only difference is the addition of today's three warehouse-post URLs. No slug, filename, or link
target was altered by any fix above.
