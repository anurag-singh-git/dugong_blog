**Nº 124 - "The refund you gave for nothing"**
`how-to-handle-shopify-returns-the-customer-never-sends-back.html` · Priya Singh · 2026-10-11 · 2,075 words incl. FAQ · 8 min

Pain point: a return is approved, a label goes out, and nothing ever arrives. The order sits at
"return in progress" for months. The merchant often refunded on approval, so the item, the money
and the processing are all gone, the unit is still counted in the inventory forecast, and nobody
can tell the difference between a customer who never posted the box, a parcel lost in transit, and
a parcel sitting unopened on the merchant's own receiving bench.

Facts used, all checked live this run:
- Flow triggers reference: seven return triggers (requested, approved, declined, processed, closed,
  cancelled, reopened). Every one fires on a status change somebody makes. Nothing fires on silence.
- Flow actions reference: cancel return, close return, reopen return. No refund action anywhere in
  Flow, no inventory adjustment action. Everything else goes through Send Admin API request.
- Shopify changelog, 16 Aug 2024, "Flow: new triggers, action and templates for managing returns":
  six new return triggers, one new action (Cancel return), three templates, one of them
  "Cancel inactive returns". The entry itself says the action helps when buyers do not send
  products back.
- Shopify Community, 20 Sept 2024, "Create flow to close returns older than 30 days" (morojp82):
  wants a Flow to close orders stuck at return in progress past 30 days. Reply suggests Get order
  data with a return status query plus a created-at cutoff, then loop and close. OP asks how to
  enter that query inside Flow. That part is never answered. Thread still has no working query.
- Shopify Community, 20 Nov 2024, "GraphQL filter orders by return_status" (TimEshopGuide):
  `return_status:open` returns nothing, `return_status:in_progress` returns the right order while
  the response warns that in_progress is not an accepted value. No replies, still open.
- Shopify dev changelog, "Filter orders by return status": the filter exists on the orders
  connection and matches the status shown on the orders page.
- Help Center, processing returns: an open return can only be cancelled if it has not been
  refunded, restocked, marked as returned, labelled, or had a fulfilment cancelled. A cancelled
  return cannot be reopened. A return closes automatically only once every item is processed and
  restocked.
- Help Center, creating returns: three shipping choices (create a label in Shopify, upload a label
  with tracking, or no shipping required). Shopify can only create the label itself when the
  primary location and the customer address are both in the United States. Inventory for exchange
  items is not reserved until the return is processed.
- Shopify Payments refunds: credit card fees are not returned on a refund.

Why it won: high, universal demand with almost nothing written for it. Page one for the intent is
return-policy and returnless-refund editorial from returns-app vendors; the only merchant-level
material is two unresolved forum threads. The "nothing happening is not an event" mechanic, the
cancel gate that blocks precisely the labelled returns you want to close, and the return_status
filter trap are all unwritten anywhere else.
Considered and dropped: serial-returner abuse detection (vendor editorial already thick, dropped by
the 10 Oct run for the same reason), partial fulfilment on a single out-of-stock line (how-to
content already dense), 3PL inventory drift (carried forward, strong candidate).
