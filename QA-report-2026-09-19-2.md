# QA report - 2026-09-19 (second run)

Scheduled autonomous run. Full-tree QA pass: structure, formatting, design, mobile, readability,
content. No new content published. Nine defects found, all fixed. Every change is CSS or an ARIA
attribute; no article prose, metadata, JSON-LD, sitemap, feed or llms entry was touched.

## Method

Structural audit ran over all 147 HTML files on disk. Rendering was verified in headless Chromium
at 320, 375, 768, 1280 and 1920 px: 39 pages swept at mobile and desktop widths, plus all 74
article titles measured against the text column at ten separate widths.

## Defects found and fixed

### 1. Article titles ran off the page (20 of 74 posts) - severe

`.article-title em { white-space: nowrap }` forced the highlighted phrase onto one line. An
existing `@media (max-width: 640px)` override let it wrap on phones, so the bug was invisible on
mobile and live on every desktop and tablet width.

| Viewport | Titles overflowing the 720 px column | Worst case |
|---|---|---|
| 1920 / 1440 / 1280 | 20 | +431 px (`how-to-automatically-request-product-reviews`) |
| 1024 | 17 | +374 px |
| 900 | 7 | +242 px |
| 768 | 4 | +100 px |
| 700 / 660 / 641 | 3 - 4 | +82 px |

Fixed by making the wrapping treatment the default at every width: the phrase now carries the
same `linear-gradient` highlight with `box-decoration-break: clone` that phones already used, and
the absolutely-positioned `::after` bar is retired. Re-measured: **0 overflowing titles at all
ten widths.** Applied to all 74 posts and to the post view inside `index.html`.

### 2. Homepage featured card clipped on phones - severe

`index.html` scrolled to 378 px inside a 320 px viewport. `.featured-card` is a grid whose `1fr`
track resolved to its min-content floor (332.5 px) instead of the 287 px content box, so the
"dispatch of the week" mock and dek were cut off mid-word. Visible at 375 px, badly broken at 320.

Fixed with `minmax(0, 1fr)` on both the one- and two-column grids, `min-width: 0` on
`.featured-visual`, `max-width: 100%` on `.playbook-mock`, and a `<= 480px` rule that wraps
`.pb-node` so the icon and status pill sit on one row and the label and sub-label get the full
width. Re-measured: scrollWidth == clientWidth at 320, 375, 768, 1280, 1920.

### 3. Topic cloud overflowed at 320 px

The longest tags ("delayed order notifications", "merge duplicate customers") are joined with
`&nbsp;`, so they could not wrap and pushed 6 px past the viewport. Added `max-width: 100%` plus a
`<= 400px` cap of `1.15rem` (the `<= 640px` cap of `1.3rem` is unchanged), which lands every tag
on one line without flattening the weighted-cloud hierarchy.

### 4. One post shipped with no stylesheet at all

`how-to-send-payment-reminders-for-unpaid-draft-orders-on-shopify.html` had the font `<link>` but
zero CSS - the page rendered as bare unstyled HTML. It is `noindex` and unwired from
index/sitemap/feed, but the URL is live and reachable. Injected the standard post stylesheet.
Verified every class the page uses is covered and the page now renders identically to its siblings.

### 5. A second draft had drifted off the shared nav CSS

`how-to-automatically-follow-up-on-unpaid-draft-order-invoices-on-shopify.html` was missing the
mobile nav rules the rest of the tree carries, so its header overflowed by 37 px at 320 px.
Re-synced; its stylesheet is now byte-equivalent to the standard one except for rule ordering.

### 6. Code inside code blocks was shrinking twice

`.article-body code` sets `font-size: 0.88em` and `.article-body pre code` did not reset it, so
code inside a `<pre>` compounded down to 10.4 px on phones. Added `font-size: inherit` to the
nested rule and raised the mobile `<pre>` size from `0.74rem` to `0.78rem`. Mobile code is now
12.5 px instead of 10.4 px.

### 7. Redirect stubs had no viewport meta (72 files)

Every stub rendered desktop-zoomed on phones for the moment before the redirect fired, and each
one fails a mobile-friendly check if crawled. Added the standard viewport tag. One line per file,
nothing else changed.

### 8. Tap targets below the 24 px minimum (WCAG 2.2 AA, 2.5.8)

`.topic` links measured 19 - 21 px tall and `.article-back` 22 px. Added vertical padding
(`.topic`: `0.35rem 0`, with the cloud's row gap trimmed from `0.75rem` to `0.35rem` so the
rhythm holds; `.article-back`: `min-height: 24px`). All interactive targets now measure >= 24 px.

### 9. No main landmark on any page (75 pages)

Nothing carried `<main>` or `role="main"`. Added `role="main"` to `<article class="article">` on
all 74 posts, and to both `.view` containers on `index.html` - only one is ever in the
accessibility tree, since the inactive view is `display: none`.
