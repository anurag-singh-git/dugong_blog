### 3. Playbook code blocks overflow horizontally on phones (46 pages)

`.article-body pre` was a single unresponsive rule at `font-size: 0.86rem` with `1.25rem` padding.
`overflow-x: auto` kept the overflow contained inside the block rather than breaking the page, so
this never showed up as a layout failure, but the readability cost on a phone is real. At a 360px
viewport the available text width inside the block is about 280px, which at 0.86rem monospace fits
roughly 34 characters. The median playbook line is 47 characters and the p90 is 58, so **every
playbook on the site required horizontal scrolling to read on a phone**, and these blocks are the
centerpiece of each post.

Added to all 46 rendered pages, immediately after the base rule:

```css
@media (max-width: 560px) {
  .article-body pre { font-size: 0.74rem; padding: 1rem; white-space: pre-wrap; overflow-wrap: break-word; }
}
```

`pre-wrap` preserves the deliberate authored line breaks and indentation while letting anything
still too wide wrap instead of scroll, so horizontal scrolling is eliminated on phones rather than
merely reduced. 0.74rem is 11.84px, above the 11px readability floor. `overflow-x: auto` is
retained on the base rule as the desktop and tablet safety net.

The 07-25 report recorded "tables / `<pre>` needing overflow handling: none present." Every post
has carried a `<pre id="playbook">` block since launch, so that check was not matching what it
claimed to.

  screens and is an editorial call rather than a QA fix — flagging it for a decision.
