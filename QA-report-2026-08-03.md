## Fixes applied

### 1. FAQ JSON-LD drifted from visible answers, 4 answers across 3 posts

Site convention is that FAQPage JSON-LD text byte-matches the rendered `.faq-q`/`.faq-a` text.
Four answers had drifted apart, small paraphrase deltas from a copy-polish that touched only the
visible surface:

| File | Answer | Drift |
|---|---|---|
| how-to-route-shopify-orders-to-the-right-warehouse.html | "Why does Shopify ship from a far warehouse..." | "may not be included in" vs "may not be in" |
| how-to-route-shopify-orders-to-the-right-warehouse.html | "Can Shopify Flow change the fulfillment location..." | "has a request status of submitted or accepted" vs "has the request in a submitted or accepted state" |
| how-to-stop-discount-code-abuse-on-shopify.html | "How do Shopify discount codes end up on coupon sites..." | "extensions like the big coupon finders" vs "coupon extensions" |
| how-to-sync-supplier-inventory-feeds-to-shopify.html | "Why does Shopify inventory sync fail..." | "a SKU read as a number in scientific notation" vs "a long numeric SKU read as scientific notation" |

Fixed by aligning JSON-LD to the visible text (the direction Google's FAQ guidelines require:
markup must match on-page content). JSON re-parsed clean on all three files afterward.

### 4. Dead anchor on the homepage featured card

`index.html` line 1627: the DISPATCH OF THE WEEK card carried `href="#post"` but no element with
id `post` exists; navigation actually happens via the `data-nav` click handler
(`showView("post")` targets `#view-post`). Changed the href to `#view-post` so the fallback anchor
resolves. Zero behavior change with JS enabled (the handler calls preventDefault).

### 5. Orphan drafts were indexable

plus the two-store inventory sync post) were fully rendered, self-canonical, and **indexable**

has **zero media queries** (not mobile-ready), which is another reason not to publish that one.

## Known non-defects, deliberately not changed

- ~35 older posts carry literal em dash characters in the title tag, RSS link title, CSS comments,
  and one marquee span, where newer posts use the `&mdash;` entity. Both render identically;
  changing 100+ spots for byte consistency would be churn with zero user-visible effect. No literal
  em or en dashes exist in any article body copy.
- Related grids on the oldest posts now hold up to ~51 cards. That is the documented mesh design
  (grid grows one card per publish). Flagging only that a future design pass may want a cap with a
  "view all" link if page weight becomes a concern; current heaviest page is ~100 KB HTML, fine.
- The pinned Aanya Rao essay is reachable only via JS view switching on the homepage (no-JS users
  and crawlers see only the JSON-LD entry). Existing design decision, unchanged.
