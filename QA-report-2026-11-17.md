after the day's publishing run had shipped dispatch Nº 142. Final state:
109 rendered pages, 82 redirect stubs, 96 dispatches, 108 sitemap URLs,

The pass lost the connection to the machine for about twenty minutes near the
start and resumed where it left off; nothing had been written at that point.
A whole-site snapshot of the 109 rendered pages was taken before the first
write at `_qa_tmp/run-11-17-qa/before.tar.gz`.

One note on method. The site loads three families from Google Fonts. The
audit container cannot reach fonts.googleapis.com, and an earlier sweep run on
the fallback stack is worthless for anything measured in pixels, because
system-ui is not Inter. The real woff2 files were installed from npm
(`@fontsource/inter`, `@fontsource/hanken-grotesk`, `@fontsource/jetbrains-mono`)
and served locally with the Google Fonts request routed to them, so every
measurement below was taken with the fonts the reader actually gets. The two
defects found are both width-dependent and neither is visible on the fallback
stack.

## Fixed

### 1. Nineteen card deks were cut off mid-sentence

`.card-dek` carried `-webkit-line-clamp: 5`, raised to 8 on tall and wide
cards. Nineteen deks across eleven pages needed six to eight lines, so each
one was truncated with an ellipsis, and because the house pattern puts the
payoff in the dek's last clause, the truncation removed exactly the sentence
the card exists to sell:

```
The order looks like every other order in your queue, it gets picked, packed
and shipped, and nine days later the payment status quietly turns to Expired.
The AI playbook that holds every one...
```

The full clause is "holds every one until the money lands". Ten of the
nineteen are on `index.html`, which is the most-crawled page on the site.

The same clamp fails WCAG 1.4.12. Measured over all 5,597 card deks: with the
text-spacing override applied, 281 deks lose content that is fully visible
without it. That is a content loss caused by the user's own spacing
preference, which is what the criterion forbids.

Both halves are one number. Measured in Chromium with the real fonts, no dek
on the site needs more than 8 lines rendered plain, and none needs more than
11 under the override, so the clamp has been raised to 12 everywhere, the one
value that truncates nothing in either case while remaining a bound. Because
nothing needs more than 8 lines today, the extra headroom costs no height at
all except where it is removing a truncation: 314px in total across all 109
rendered pages, and +24px on the desktop homepage, which is 12,980px tall.
Re-measured after the change: 0 deks clipped plain, 0 clipped under the
override, at 320, 375, 768 and 1280px.

### 2. Six playbooks were scroll regions a keyboard cannot reach

The base `.article-body pre` rule set `overflow-x: auto` and left
`white-space` at its initial `pre`. The playbooks are hand-wrapped to about
45 to 53 characters a line, but six of them carry a line of 71 characters,
which renders 588px wide against a 580px content box. Eight pixels over, and
the block becomes a horizontally scrollable region:

- the last 8px of that line is clipped, and only a mouse drag reveals it;
- the region has no `tabindex`, so a keyboard user cannot scroll it at all,
  which is WCAG 2.1.1.

The `max-width: 820px` rule has set `white-space: pre-wrap; overflow-wrap:
break-word` on these blocks since they were written, so every one of these
playbooks already wraps on a phone and the house has long accepted that
rendering. The same two declarations are now on the base rule, which fixes
the six pages and closes the class: a long line written by a future run wraps
instead of silently reopening the hole. `overflow-x: auto` is kept for a token
that genuinely cannot break. Re-measured: 0 scrollable `pre` without keyboard
access at any of the four widths.

Affected: `how-to-add-alt-text-to-shopify-product-images-in-bulk`,
`how-to-automatically-cancel-unpaid-orders-on-shopify`,
`how-to-automatically-request-product-reviews-on-shopify`,
`how-to-automatically-tag-orders-on-shopify`,
`how-to-bulk-edit-meta-descriptions-on-shopify`,
`how-to-validate-shipping-addresses-on-shopify`.

## Tried and backed out

**A print stylesheet.** Not one of the 109 rendered pages carries an
`@media print` block, so a reader printing a playbook gets the marquee
ticker, the sticky nav and the footer's four link columns. That is a real gap
and it has the familiar shape of the `:focus-visible` and
`prefers-reduced-motion` gaps fixed on 11-02 and 11-04.

A conservative block was written and shipped to all 109 pages, and then
removed, because rendering it proved it made printing worse rather than
better. Dispatch Nº 142 printed to **14 A4 pages with no print CSS at all and
17 to 18 with it**, including one page holding nothing but an empty
`.short-answer` box. Two causes, neither of which a careful first draft
avoids: `break-inside: avoid` on containers taller than a page makes Chromium
leave the page blank and move the content, and unclamping `.card-dek` for
print expands every READ NEXT card to full length. The right fix needs a
decision this pass should not make unattended, because `.related` is
navigation on a dispatch and content on a topic guide, so a rule that hides
it helps one page type and empties the other.

Left for a run that can look at the output and decide. The measurement above
is the starting point; `_qa_tmp/qa-fix-2026-11-17.py` still holds the block
that was tried, as a record of what not to ship.

## Checker

Two invariants added to `_tools/seo-check.py`, both verified fail-loud against
a planted defect in the tree at the end of the pass, per the lesson recorded
on 11-16:

- `card_dek_clamp_too_low`: no `-webkit-line-clamp` below `CLAMP_MIN = 12`.
  Planted `-webkit-line-clamp: 5` in `index.html` and the run reported it.
- `pre_does_not_wrap`: the base `.article-body pre` rule must declare
  `white-space: pre-wrap`. Planted its removal in
  `how-to-validate-shipping-addresses-on-shopify.html` and the run reported it.

Both plants were reverted and the checker returns to PASS on the current tree.
