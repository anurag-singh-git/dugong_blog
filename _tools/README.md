# _tools

Checked-in helpers for maintaining blog.dugong.live.

The leading underscore does **not** hide this directory. The repository has a
`.nojekyll` file, so GitHub Pages serves it raw and never runs Jekyll, which
means `_tools/` is fetchable on the live domain like any other path. robots.txt
disallows it in every user-agent group and says so in its own header comment.
Corrected 2026-10-24; the earlier wording here claimed the opposite and would
have led a later run to commit something here believing it was unreachable.

## seo-check.py

The field-level invariant checker. Run it from the repository root at the end
of every blog run and every SEO/GEO pass, before committing:

```
python3 _tools/seo-check.py          # full output
python3 _tools/seo-check.py --quiet  # first 10 entries per failing category
```

Exit code 0 means every invariant holds; 1 means at least one does not. No
dependencies beyond the Python standard library, so it runs in either shell.

It checks the things the daily run has actually broken before, which is the
reason it exists rather than a general-purpose linter:

### A fix that was measured and not shipped

2026-11-17: no rendered page carries an `@media print` block, which is a real
gap of the same shape as the `:focus-visible` and `prefers-reduced-motion`
gaps. A conservative block was written, shipped to all 109 pages, rendered,
and removed: dispatch Nº 142 printed to **14 A4 pages with no print CSS and 17
to 18 with it**, one of them holding nothing but an empty `.short-answer` box.
`break-inside: avoid` on a container taller than a page makes Chromium blank
the page and move the content, and unclamping `.card-dek` for print expands
every READ NEXT card. A correct version has to treat `.related` differently on
a dispatch, where it is navigation, and on a topic guide, where it is the
content. The lesson for this file: **render the output before believing a
stylesheet improves it.** A print rule cannot be reasoned about from source.

### Deliberate exceptions

`EXCEPTIONS` near the top of the file holds the handful of cases where a
check is intentionally not applied, each with the reason in a comment:
`index.html` and `404.html` keep hand-written og:/twitter: copy, the lead
essay's `lastmod` and `dateModified` legitimately differ, `404.html` is
noindex and unlinked by design, and `wikidata_only_entity` lists entities
whose concept has a Wikidata item but no English Wikipedia article. That last
one is a tightening rather than a loosening: an entity on that list must
carry Wikidata and must **not** carry a Wikipedia URL, because the only
candidate pages are disambiguation pages or near-miss concepts. Add to it only
with a reason, and only after checking both APIs in both directions.

### If a check fires on something that is actually correct

Do not loosen the check. Either fix the page or add the page to the matching
`EXCEPTIONS` entry with a comment saying why it is intended. A checker that
has been relaxed to pass is worth nothing.

## render-diff.js

Proves a change moved nothing a reader can see. Renders each page from two
directories in headless Chromium at 1280 and 390 CSS pixels and compares four
channels: the rendered DOM with the `ld+json` blocks stripped, the geometry and
paint of every element, the visible text, and the full-page screenshot.

```
node _tools/render-diff.js <dir-A> <dir-B> [page.html ...]
node _tools/render-diff.js <dir-A> <dir-B> --control   # A against itself
```

Needs Chromium and Playwright, which are in the cloud container and not in the
desktop shell, so stage both trees and run it there.

Added 2026-11-17 because the recipe the 11-16 report left behind did not work.
That report's lesson was "freeze animation before diffing this site, or the
masthead marquee reports a false positive on every page", and it is half the
story. **This site has two animation families**: the marquee (`.ticker-track`)
and the `.reveal` entrance transition that every article paragraph and heading
carries. And a freeze injected after `load` does not help with either, because
it stops the animation at whatever phase it had reached and that phase is not
reproducible. Measured on 2026-11-17, with the post-load freeze the 11-16
report describes: rendering **one file twice** reported 4 of 8 page-widths
different and 116 of 1185 elements off by a single pixel, with identical DOM
and identical visible text. The freeze here is injected with `addInitScript`,
before the first paint, and names the resting state of both families.

**Always run `--control` first.** On this site a harness that cannot report one
tree identical to itself cannot report two trees identical to each other, and
the failure looks exactly like a real regression.
