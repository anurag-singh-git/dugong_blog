**Dispatch Nº 120 - "The automation that quietly stopped running"**
`how-to-catch-shopify-flow-workflows-that-fail-silently.html` · by Priya Singh · 2026-09-20 · 2,771 words (stated 2,700) · 11 min

Topic: Shopify Flow does not tell you when it breaks. The run list marks a run Completed whenever
it stops, whatever its actions did; the built-in error trigger fires once per workflow version per
thirty days; run history is deleted on day fourteen; and a workflow that stops firing altogether
produces no run at all, so the one screen merchants check cannot show the most expensive failure.
The post covers the five failure modes, the community record, the platform-side breakages, and the
playbook that watches outcomes instead of logs.

Facts carried, all read live this run:

- Shopify's monitoring documentation defines the five run statuses. In progress is "currently
  executing or retrying", Waiting is "a wait step has delayed a workflow", Rate limited is "the
  workflow was using too many resources, so Flow limited the execution", Canceled is "the workflow
  was canceled before it could complete", and Completed is, in full, "done".
- January 2, 2026, developer forum: a run reported Completed while an HTTP request failed inside a
  loop. "I am not sure why the 'Run status' shows as 'Completed' when one action had an error."
  Shopify staff confirmed and explained: "The 'fail' will stop execution for that path, which is
  usually the same as the workflow. However, here you have many paths because you have actions
  running in parallel and a loop." Completed does not mean successful.
- The Workflow error occurred trigger "starts a workflow when workflows fail during execution",
  and runs once per workflow version within a 30-day period however many times the workflow fails;
  the counter resets on an edit (new version) or after 30 days. The troubleshooting page states the
  intent: "Error notifications are designed to limit noise, so you will only get one notification
  per workflow version."
- Retention: "Workflow runs are stored for 14 days after a run has completed. After 14 days, the
  run is removed from the system." The run search is "limited to the last 14 days of workflow runs."
- April 1 to 3, 2025: a signup automation stopped sending. "It worked for several month correctly.
  Since Monday it does not work anymore." Staff first pointed at third-party forms and marketing
  consent, then: "Turns out there was an issue with a recent release that was causing issues with
  double opt-in. The issue should be fixed now."
- May 29 to 30, 2025: a Plus merchant's company-metafield action began submitting a list where a
  single integer belonged. "Today we went to test it again (had used it before and worked perfect)
  and it was erroring." Fixed by saving the workflow against a different metafield and switching it
  back: "something on the Shopify/Plus side had started trying to update with the wrong type and
  resetting it fixed it."
- September 26, 2024: workflows stuck In progress and failing halfway, three merchants in one
  thread. "I'm assuming it's some update on the backend of shopify or flow that is causing this
  error." No staff answer in the thread.
- February 3 to 9, 2026: a "Recent runs contain errors" banner sitting above runs that showed no
  errors. Three staff replies over six days, a search-filter workaround, no cause identified.
- Limits that do not announce themselves: 1,000 workflows per store, 40 wait steps per workflow,
  90 days of total wait time, 36 hours combined execution per workflow section, 50 kB per config
  field, and Get data actions "designed to return a maximum of 100 objects per workflow".
- March 24, 2026 changelog: a Get workflow run data action that "retrieves information about a
  workflow run, including the workflow it belongs to, the event that triggered it, retry attempts,
  and timing details", so merchants can "build workflows that monitor or report on other workflow
  activity". Useful, and still a workflow watching workflows inside the failing system, on data
  that expires in 14 days, blind to a run that never started.
- December 12, 2025, Shopify's own Flow round-up: "Workflow runs that fail now stop when you tell
  them to. Cancel runs individually or in bulk while they're waiting or retrying."

Honest limits stated in the post and the FAQ: this shortens the distance between breaking and
knowing rather than preventing the break; it cannot audit an automation nobody wrote down; and a
genuine anomaly such as a flash sale will generate noise unless somebody tells it the week is not
normal.
